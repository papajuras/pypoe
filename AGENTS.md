# pypoe — Path of Exile personal sidecar

Personal utility for Path of Exile crafting and economy monitoring.

## Token / cost discipline
- Be very considerate of tokens and money. Minimize output length, batch tool
  calls, skip unnecessary exploration, don't read whole files when a grep will
  do. Prefer the smallest edit that answers the question.

## Behavioral contract
- Don't assume intent. If a request is ambiguous or has several plausible
  readings, ask before doing anything — never pick one silently. One question
  beats redoing wrong work.
- Fail fast, report. If something can't be done in the current mode, or the
  result is missing/uncertain, say so immediately — don't improvise substitutes.
- Shortest feedback loop: do the smallest thing that answers the question, then
  stop and report. No speculative follow-ups, no "while I'm here" work, no
  extra requests the user didn't ask for.
- Don't invent. Never claim data exists unless verified (grep/read it). If I
  said something earlier that turns out wrong, correct it explicitly rather
  than papering over it. When uncertain, say "I don't know" and check.
- Ask before expanding scope. If a request implies more work than stated,
  confirm the direction first instead of guessing.
- **NO long `sleep` commands. Think 10 times before sleeping at all:
  do we really need it?** A wait is almost always the wrong tool — poll with a
  short bounded loop, check state once more, or just report and let the next
  command verify. If a sleep is genuinely unavoidable, the command MUST carry
  a comment stating the goal and what exactly we expect to observe afterwards
  (e.g. `# waiting for deploy health check; expect HTTP 200 within 10s`).
  Sleeping blindly on the user's time is not acceptable.


## Features

### 1. Alt/Aug/Regal/Exalt crafting spammer (app/)
Automates orb usage with configurable stop criteria.
- Alt-spams items, augments when hitting desired mods, regals/exalts based on match count
- Profiles define which prefix/suffix mods to look for (saved to app/pypoe/data/crafting.json)
- Influenced mods detected automatically from spawn weight tags
- Game-accurate display text from RePoE stat_translations.json (cached in app/pypoe/data/cache/)
- Hotkeys: Ctrl+J to start spam, ESC to stop
- Debug button shows current prefix/suffix match arrays
- Vue 3 SPA with affix browser, profile manager, orb toggles, screen modes

### 2. PoE Trade flipping (gatherer/ — remote data gatherer)
Flipping opportunity monitor with automated price fetching.
- Flips defined by source (buy) + target (sell) trade queries, multiplier, cost
- TradeClient with strict rate limiting (stagger + buffer, parses X-Rate-Limit-* headers), curl_cffi with `impersonate="chrome110"` for the Cloudflare TLS fingerprint
- PriceFetcher scans every 30s for oldest-unpriced flips, fetches live prices via worker thread; scheduler gives near-break-even flips a 30-min cadence to catch trend reversals
- Source: average of 5 cheapest listings; sub-divine items priced in chaos too
  (`source_chaos_avg`/`source_chaos_count`, schema v8) and blended to divine **app-side** by the BFF
  (`_blend_source_chaos`, weighted avg at the ninja divine rate for `_last_league`) — the ratio never
  ships to the Pi. Target: cheapest single divine listing.
- Profitable/not-profitable split, sortable by cost/profit/profit%, auto-refresh every 3s
- poe.ninja integration: items priced via ninja API (DivinationCard, Currency) with ETag cache.
  Cache is keyed by `(league, type_key)` — a Standard↔Allflame collision bug is fixed.
- **Single flip key**: the short autogenerated id (`uuid4().hex[:12]`, the flips PK) is used
  everywhere — DB (flips/prices/history/listing_snapshots + local mirrors), API, BFF cache, and FE.
  The `uuid` column survives in the schema but is no longer exposed or used for lookups.
- SQLite store with schema migrations, price history table, 60-day auto-prune
- Price history (source_avg/target_avg + source_total/target_total listing counts, epoch-ms) exported via
  `GET /api/history?since=<ms>`; local app mirrors it (app/pypoe/data/history.db, dedup via INSERT OR
  IGNORE, 60-day prune) — the gatherer only gathers
- Target-side listing snapshots: every reprice stores up to 10 sell offers
  (`listing_snapshots` table: rank/seller/amount/currency/indexed_ms/ilvl/rarity, 60-day prune,
  one commit per flip). Trade fetch is capped at 10 listings/request — no extra requests.
- Gatherer `GET /api/status` reports `db_size` (flips.db + WAL bytes); SPA shows a DB-size pill.
- Runs as its own process (deployed to a Raspberry Pi on the home LAN; BFF proxies to it)

### 3. Flip journal (app/ — local SQLite)
Manual log of personal flips: definition (base+quality from `app/pypoe/db/bases.py` GROUPS,
the single source of truth shared with the generator), cost, gross income (NULL = unsold),
net = income - cost. League stamped from the gatherer at creation for future history queries.
- Store: `app/pypoe/flipper/journal.py` → `app/pypoe/data/journal.db` (table `journal`,
  inline CREATE IF NOT EXISTS). One-time legacy import from `ignore/flips` (kept untouched;
  one row = one flip, `cost` = Σ negative numbers, `income` = Σ positive numbers, NULL = unsold).
- BFF: `GET /api/journal` (records+definitions+league), `POST /api/journal`,
  `PUT /api/journal/{id}`, `DELETE /api/journal/{id}`. `update` uses `_MISSING` sentinel so
  `None` clears income (reopens), absent key leaves unchanged.
- FE: "create flip" `J` button on each flipper row jumps to the Journal tab, pre-selects the
  matching definition (journal def label == flip name), and pre-fills Cost from the flip's
  blended `source_avg`. Hidden for manual flips with no matching journal def.
- Test: `PYTHONPATH=app .venv/bin/python3 app/tests/test_journal.py` (7 asserts)

### 4. Market analysis (app/ — local, two engines)
`GET /api/analysis?flip_id=<id>` returns two independent views over the target-side
`mirror.snapshots()` history, shown in a hover popover on the analysis pill (📊/⏳/%/—).
- **Complex** (`app/pypoe/analysis/`): Gamma-Poisson survival — `engine.classify_events`
  (SOLD/PRICEDROP/CENSORED), `prior.resolve_prior` (pooled per item-type/tier), `survival.compute_cif`
  → P(sell≤1d/3d/7d) table. Needs 20+ intervals or falls back to DEFAULT_PRIOR.
- **Simple** (`app/pypoe/analysis/simple/`): common-sense, works with ≥2 snapshots. Fits
  least-squares slopes for min-price and stock → 4 categories (🔥 Hot 9 / ♨️ Warm 7 / 🌬️ Cool 5 /
  ❄️ Cold 3) plus `turnover_per_day` (cheapest offers gone per day, 48h relist exclusion).
  The BFF always returns `simple` even when the complex engine is `insufficient_data`.
- Both are `_demo()`-asserted (`app/tests/test_analysis.py` runs engine/prior/survival/__init__;
  simple runs standalone).

## Architecture

Two decoupled Python packages, each with its own `pyproject.toml`:

```
repo/
├── app/                       # LOCAL: BFF + crafting + Vue SPA
│   ├── main.py                # entry point (keyboard listener + servers)
│   └── pypoe/
│       ├── config.json        # gatherer URL, screen_mode, selected profile
│       ├── config.py          # reads app/pypoe/config.json
│       ├── crafting/          # session/actions/matching/controller
│       ├── analysis/          # market analysis (complex survival + simple/ trends)
│       ├── db/                # affixes (RePoE), profiles config, generator, tool
│       ├── flipper/           # api.py (BFF), gatherer_client, static_server, static/
│       ├── data/              # gitignored: crafting.json, RePoE cache
│       └── tests/             # affix filtering / cluster / life-block asserts
└── gatherer/                  # REMOTE: data gatherer (ssh to Pi)
    └── gatherer/
        ├── config.json        # league
        ├── config.py          # reads gatherer/gatherer/config.json
        ├── server.py          # HTTPServer (port 23467) — flips/health/league/settings
        ├── client.py          # TradeClient
        ├── ninja.py           # NinjaClient
        ├── pricer.py          # PriceFetcher (scanner + worker)
        ├── store.py           # Store + Flip (SQLite)
        ├── schema.py          # versioned migrations (flips/prices/history/meta)
        ├── uuid7.py           # UUID v7 helper
        ├── data/              # gitignored: flips.db, POESESSID, logs
        └── tests/             # test_throttle (18), test_pricer (11), test_store (8), test_scheduler (16)
```

- Config is in 2 files, none at repo root: `app/pypoe/config.json` + `gatherer/gatherer/config.json`.
- App logging is **file-only** (`log/app.log`): `main.py` uses `logging.basicConfig(handlers=[FileHandler])`
  (no StreamHandler → nothing on stdout/stderr); startup URLs, mouse-pos, and beast-delete messages
  go through `logger.info` too. Gatherer logs stay on the Pi.
- Quality checkboxes (`flipper_quality_27..30`) live in the gatherer's flips.db `meta` table,
  exposed via `GET/PUT /api/settings` and proxied through the BFF.
- `POESESSID` is a plain gitignored file at `gatherer/gatherer/data/POESESSID`.

## Tech stack
- Python 3.13, uv for package management (root pyproject = app deps)
- Vue 3 + Tailwind (static HTML, served by stdlib http.server)
- pyautogui / pynput / keyboard for automation
- SQLite via stdlib, curl_cffi, requests/httpx/websockets for APIs

## Hard rules
- **NEVER delete or clear gatherer/gatherer/data/flips.db** — contains real data
- **NEVER delete or clear app/pypoe/data/crafting.json** — contains real crafting profiles
- **NEVER clear data just because schema changed** — use gatherer/gatherer/schema.py migrations
- **NEVER start the gatherer locally** — it runs only on the Pi. Two local processes
  with different POESESSIDs = two PoE sessions from one IP = rate-limit ban risk. Local dev
  always connects to the Pi gatherer via `app/pypoe/config.json` → `gatherer` URL (`pi.local`).
- **NEVER run the gatherer without the VPN netns** — the gatherer MUST run inside the
  `pypoe-vpn` netns (WireGuard, ProtonVPN) or it cannot reach the trade API (the GCP
  datacenter IP was Cloudflare-blocked; the netns is kept on the Pi as belt-and-suspenders).
- `bin/test-net.sh` — health harness (ssh/host-egress/netns-egress/gatherer/LAN). If checks
  1-2 fail the host networking is bricked → reboot the Pi, re-run.
- Data dirs (`app/pypoe/data/`, `gatherer/gatherer/data/`) are gitignored and preserved
  across deploys (scp/rsync excludes them)
- **NEVER delete or overwrite anything under `ignore/`** (e.g. `ignore/flips` = user's
  manual flip journal, `ignore/*.conf` = VPN configs) — user-manual data, gitignored.

## How to run (local dev)
```
./run.sh
```
Starts only the app (BFF 8765 + static 8766), opens nothing (headless; browser manually).
The app talks to the gatherer at the URL in `app/pypoe/config.json` — the gatherer
itself runs on the Pi (never locally), inside the `pypoe-vpn` netns.

## Deploying the gatherer (bin/deploy.sh)
Ships the `gatherer/` module + the VPN config (`ignore/*.conf` → `/etc/wireguard/wg0.conf`)
+ `bin/pypoe-vpn.sh`, installs systemd units, restarts. Re-runnable. The gatherer systemd
unit runs via `ip netns exec pypoe-vpn setpriv ...` so its traffic egresses through the
WireGuard tunnel while host SSH stays on the main network. Target: `ssh pi`.

## Cloudflare / VPN notes
- The GCP datacenter IP was blocked by Cloudflare (403 on every PoE trade request)
  regardless of TLS fingerprint — the VPN netns is mandatory, not optional. On the home
  IP it's belt-and-suspenders (kept anyway).
- The TLS fingerprint (curl_cffi impersonate chrome110, pinned curl-cffi==0.15.0 in
  gatherer/pyproject.toml) alone does NOT get through from a datacenter IP; it matters
  only on a non-blocked IP.
- VPN config lives at ignore/*.conf (gitignored, ProtonVPN WireGuard) → shipped by
  bin/deploy.sh to /etc/wireguard/wg0.conf.
- pypoe-vpn.sh adds the LAN subnet to the netns main table after wg-quick up, else wg-quick's
  policy routing (table 51820) sends replies to LAN clients into the tunnel and the BFF can't
  reach the gatherer. This is the fix behind `bin/test-net.sh` check 5.
